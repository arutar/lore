# ADR-0002: Read-only MCP endpoint with personal tokens

## Context and Problem Statement

Teams want AI agents (Claude Code, Cursor, Hermes with any model) to look through Lore repositories:
find a file, read code and configuration, follow the history, see who holds a lock. The usual way to
offer that is the Model Context Protocol (MCP): the agent is given a server address and a
credential. Lore holds a studio's source and assets, so whatever an agent can do through MCP has to
be safe even when the agent misunderstands an instruction or reads a file written to mislead it, and
the setup has to stay simple for both the administrator and the person connecting an agent. The
server runs inside company networks and, for some installations, is reachable from outside.

## Decision Drivers

- Nothing can be deleted or changed through MCP.
- An agent never reads more than the person who connected it may read, now, not at the time the
  credential was made.
- Any MCP client works, including ones that only take a URL and a header.
- An administrator can stop a person, a group or everyone without hunting for credentials.
- The server stays responsive for people when an agent misbehaves.
- No new service to deploy and no dependency on an OAuth flow.

## Considered Options

1. **Read-only tools on the control plane, personal tokens** (chosen).
2. Reuse the WebUI session or the native client's OIDC tokens: no way to hand a credential to an
   agent without handing over the person's whole session, and the five-minute exchanged tokens don't
   suit long-running agents.
3. OAuth 2.1 authorization as the MCP specification describes, with Keycloak as the authorization
   server: needed only for clients that can't take a static header; Keycloak's dynamic client
   registration and consent would add moving parts for no gain in the clients this is for.
4. A separate MCP service talking to the control plane's API: one more container, a second copy of
   the access rules.

## Decision Outcome

Option 1.

### How it works

- `POST /mcp` on the control plane is a stateless MCP server (Streamable HTTP, JSON-RPC answered
  with plain JSON, no sessions, no server-initiated messages). `GET` and `DELETE` answer 405.
  It speaks protocol versions 2025-11-25, 2025-06-18 and 2025-03-26.
- **Only read tools exist**: `list_repositories`, `get_repository`, `list_files`, `file_info`,
  `read_text`, `download_link`, `history`, `revision_changes`, `list_locks`. All carry
  `readOnlyHint: true`. They use the same store and Lore content client as the WebUI handlers.
- **Tokens.** `lore_mcp_` and 43 base62 characters (256 bits). Only the SHA-256 is stored (table
  `mcp_tokens`); the secret is shown once. A token belongs to one account, may be limited to some
  repositories, and doesn't expire unless its owner chose an expiry. Every request needs one, also
  for public repositories; the WebUI session cookie is ignored on `/mcp`.
- **On every request**: the token exists, isn't revoked or expired; its account exists and is
  active (a directory account's groups and state are refreshed as for the WebUI); MCP is allowed
  for the account; then each tool checks `policy.CanRead` against the repository's grants and the
  token's repository list. A repository that can't be read answers exactly like one that doesn't
  exist.
- **MCP switch.** `users.mcp_disabled` for local accounts and `directory_access.mcp_disabled` for
  entries of the Active Directory access list, both on by default. A directory account with a
  personal entry follows that entry; one admitted only through groups may use MCP when any of its
  enabled groups allows it (`model.MCPAllowed`). The personal setting wins because it's the
  administrator's explicit decision about that person.
- **Files.** `file_info` returns metadata only and classifies the first 8 KB: NUL byte → binary;
  UTF-8/UTF-16 byte-order mark → text; valid UTF-8 → text; otherwise "text, not UTF-8". Encodings
  aren't guessed: `read_text` decodes only an encoding the caller names (WHATWG names through
  `golang.org/x/text/encoding/htmlindex`). `read_text` streams the file, returns numbered lines in
  parts bounded by `LORE_MCP_MAX_READ`, and with `pattern` searches the file without returning it
  (RE2 for regular expressions, at most 200 lines shown).
- **Downloads.** `download_link` stores the SHA-256 of a random 32-byte key with the token, account,
  repository, path and revision (`mcp_links`) for `LORE_MCP_LINK_TTL`. `GET /mcp/download/{key}`
  needs no token, so a person can open it, but repeats every check of a request (token, account,
  switch, grants, network) before streaming the file. Revoking a token deletes its links. Each link
  is an audit event (`mcp.download`).
- **Limits.** A tool call has 25 seconds (inside the router's 30-second limit, so the agent gets a
  readable error rather than a gateway timeout). `LORE_MCP_CONCURRENCY` (8) calls per token run at
  once; another gets "busy" immediately. There is no rate limit: every call is attributable to a
  person and a revocable token.
- **Network.** `LORE_MCP=off|internal|on`, default `off`; `off` registers no route. `internal`
  answers only client addresses in `LORE_MCP_NETWORKS`, which the administrator must give. The
  address is `X-Real-IP` as Caddy sets it from the connection (`{client_ip}`), with any
  client-supplied `True-Client-IP` removed, so a client can't claim an internal address.
- **Browsers.** A request with an `Origin` other than the WebUI's own is refused, so a web page
  can't drive MCP from a person's browser.
- **Audit.** Token creation and revocation, switch changes and download links. Reads aren't
  recorded; a token's `last_used_at` is updated at most once a minute.

### Consequences

- Agents get a useful view of repositories with no way to change them. Write tools (locks, commits)
  would each need their own decision; nothing in this design blocks adding them behind a token scope.
- A leaked token reads what its owner may read until it's revoked or its owner is switched off; the
  token list shows when each was last used. Tokens that don't expire are the owner's choice.
- `internal` depends on Caddy seeing real client addresses. Behind another proxy administrators list
  the proxy's address or use `on`. Docker Desktop (checked on Windows) presents every connection from its
  own gateway address (seen as `172.21.0.1` on the test stand), so `internal` needs a Linux host;
  refused addresses are logged.
- The WebUI's MCP page lives at `/mcp-tokens`, since `/mcp` is the endpoint itself.
- Clients that only accept OAuth can't connect; `mcp-remote` covers clients that only start local
  servers.
