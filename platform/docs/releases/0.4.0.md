## What changed

Lore Platform 0.4.0 brings the Lore client to Linux desktops and the upstream Lore changes of
November 23–24.

**Linux client**

- Packages for Rocky Linux and RHEL 9 (`.rpm`), Ubuntu 24.04 and Debian 13 (`.deb`). `lore-client`
  installs the `lore` CLI, and in GNOME Files, Nemo and Caja the same context menu, status icons and
  operation windows as the Windows client. `lore-client-dolphin` adds the menu and status icons to
  KDE Dolphin, on KDE Frameworks 5 or 6 as the system has it.
- The menu: outside a working copy **Lore Clone...**; inside one **Lore Sync**, **Lore Commit...** and
  the **Lore** submenu (stage, unstage, revert, resolve conflicts, status, history, locks, accounts).
  The windows are the Windows client's: the Commit window with its file tree, the questions before
  anything that could lose work, sign-in and accounts.
- Status icons as on Windows: modified, staged, staged and modified, conflicted, locked, ignored,
  and clean on a working copy's root; a folder shows the strongest state inside it. They update
  after every Lore operation, and open windows redraw at once.
- The WebUI's home page offers the package of your system with its install command, the Dolphin
  package beside it, and the CLI archive for other distributions.

**Windows client**

- The Commit window's progress while sending showed wrong numbers since 0.3.1; it reads the push
  progress again. The History window shows revision hashes.
- The companion's operations moved into a library the Windows and Linux clients share; the windows
  and Explorer integration are unchanged.

**WebUI**

- Users and groups on a phone: the role sits next to the name, the MCP and Active switches below it.

**Upstream Lore, November 23–24 (12 changes)**

- Server: an unreachable repository answers "not found" on lookup and delete; presigned URL mints and
  redemptions are logged without their tokens.
- Client: sync and status say "not logged in" without a valid login; the repository service gets the
  access token when there is no identity token.
- Links: conflicts at a link mount resolve with mine or theirs; every mount of a linked repository
  stays at one pin.
- Working copies on SWFS, Epic's virtual file system, can commit.
- Memory: allocator heaps of idle threads are given back.

**Upgrading**

Deploy the 0.4.0 server bundle and images and run setup: the home page then lists the Linux packages
(`LORE_CLIENT_DOWNLOADS=offline` downloads them to the server too). The server and its protocol
don't change otherwise; 0.3.x clients keep working.
