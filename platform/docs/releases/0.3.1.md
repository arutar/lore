## What changed

Lore Platform 0.3.1 brings in the upstream Lore changes of November 8–23, and makes the
administrator's list of MCP tokens usable with many tokens.

**MCP tokens**

- **Everyone's tokens** is a table: owner (name and login), token, what it may read, last use and
  expiry, status and **Revoke**. It searches by the owner's name, login or email and by the token's
  name, and loads 50 at a time.
- Each token shows whether it works now: *Works*, *MCP off* (switched off for its owner), *User
  disabled* (its owner is disabled, or no longer admitted from Active Directory) or *Expired*.
- Deleting an account revokes its tokens and their download links.

**Upstream Lore, November 8–23 (215 changes)**

- Push: the server prefetches the node blocks a push changed while it verifies the revision, which
  shortens the verification of very large revisions. A push killed after the server accepted it is
  recognised when it's run again.
- Working copies: staging and marking wide directories no longer slow down with the number of
  files in a folder; a directory deleted as a whole syncs as one change; case-only renames of
  folders keep their contents; status, stage and the dirty marks agree on removed and replaced
  paths.
- Storage: an interrupted download of a file of 32 MiB or more resumes; sparse files keep their
  holes on Windows (NTFS, ReFS) and macOS.
- Transport and server: fewer lock waits under bursts of reads; a failed authorization check is an
  error rather than "not found".
- The `lore` client reports version 0.14.1.
- The fork's changes stay: push as a server-side operation with progress, anonymous clone, working
  copies on network shares, the durable lock store and the push lock guard.

Measured on the test stand against 0.3.0 (one run each, Windows client, LAN): committing and
pushing 200,000 files, committing an 8 GiB file and cloning 200,000 files take the same time
within 2 %.

For SDK readers: the server's push verification progress, which 0.2.8 sent as a separate event,
now arrives on `BranchPushFragmentProgress` in the new trailing fields `server_phase`,
`server_restarts` and `server_checked`, since upstream's event list reached the 256 events it can
hold.

**Upgrading**

Deploy the 0.3.1 server bundle and images and run setup. Migration `014_mcp_token_list.sql` adds
two indexes.
