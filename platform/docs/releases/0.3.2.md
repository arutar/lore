## What changed

Lore Platform 0.3.2 moves the server's push verification progress onto an event of its own.

**For SDK and C API readers**

- The progress of the server verifying a pushed revision arrives on the generic `Progress` event
  (`LORE_EVENT_PROGRESS`). Its data, `lore_progress_event_data_t`, now carries the repository, the
  branch, `server_phase` (1 preparing, 2 verifying fragments, 3 merging onto a branch that moved,
  4 moving the branch, 5 running the post-push hooks), `server_restarts` and `server_checked`.
  Upstream Lore sends no `Progress` event and still defines its data as a placeholder.
- `BranchPushFragmentProgress` is back to upstream's layout: the trailing `server_*` fields 0.3.1
  added to it are gone, and it reports fragment transfer only.
- Every event id stays as in upstream Lore. Upstream's event list holds the 256 events it can, so
  the fork can't add an event of its own; when upstream reworks `Progress` into per-command
  progress, the fork will move onto that.

The `lore` CLI and the Windows Companion read the new event; their progress display doesn't
change.

**Upgrading**

The server and its protocol don't change; the change is in the client library, which each
client carries with it. Update the clients; any 0.3.x client keeps working against a 0.3.2
server. A program built against `lore.h` of 0.3.1 that read the `server_*` fields of
`BranchPushFragmentProgress` reads them from `Progress` now.
