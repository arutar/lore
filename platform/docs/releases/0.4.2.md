## What changed

Lore Platform 0.4.2 brings in upstream Lore up to 486a5404 and moves push verification progress
onto an event of the fork's own.

**Upstream Lore**

- Upstream main is merged up to 486a5404 (60 changes since 0.4.0). Among them: the AWS stores use
  Lore's own S3 and DynamoDB client instead of the AWS SDK; clone writes every file at its own path,
  without a temporary file; the branch list shares and range-reads its store reads; repositories can
  be renamed through the C API; the server cancels requests a client abandoned; QUIC streams write
  responses together. The upstream notes are in `docs/release-notes/`.
- Upstream encodes events by their position, so there is no longer a limit of 256 events, and it
  removed the C API's `LORE_EVENT_ERROR` event: a failure arrives in `Complete`.
- A client and the Lore service now compare the schemas of their builds and the service refuses a
  client of another build (`Lore service unavailable`, exit code 32).
- `lore service stop` reports a service of an older build as unavailable (exit code 32) when that
  service closes the connection before the stop request is written, where it reported
  "Broken pipe".

**Push verification progress**

- The server's verification progress (phase, restarts, files checked) now arrives in the fork's own
  event `ForkBranchPushVerifyProgress`, C tag `LORE_EVENT_FORK_BRANCH_PUSH_VERIFY_PROGRESS` (65536).
  `Progress` is upstream's again. Fork events stay last in the declaration with tags from 65536, so
  upstream's tags never move; a test in `lore-capi` checks it.
- `lore branch push` and the Commit window in Companion show the same phases as before
  ("Server is verifying the revision · preparing → running server hooks").

**Upgrading**

Deploy the 0.4.2 server bundle and run setup, then update the clients. After updating a client,
stop a running Lore service with the `lore` it came from (`lore service stop`) or end its process:
a service of the previous build refuses the new client. A C caller that read
`LORE_EVENT_PROGRESS` for verification progress reads `LORE_EVENT_FORK_BRANCH_PUSH_VERIFY_PROGRESS`.
