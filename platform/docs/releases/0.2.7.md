## What changed

Lore Platform 0.2.7 updates the server, Windows Companion and Linux CLI for pushes that take longer to verify than a single network request can stay open.

- After uploading the files, Companion and the CLI show that the server is verifying the revision. The client starts a server operation and polls its status. A dropped response can be retried with the same operation ID.
- The file-backed server and the DynamoDB backend record the branch update and its result atomically. If another user pushes immediately afterwards, the first client can still retrieve the revision its own push produced.
- The server continues working if the connection drops. If the server process stops during verification, the next status request can resume the operation after its 60-second lease expires. A rejected push also retains its error details.
- Existing clients can still use the original push endpoint. Updated clients use that endpoint when connecting to a server that does not implement the new protocol.

## Verification

Local end-to-end tests exercised the file-backed server and DynamoDB Local. Each test pushed two revisions, killed and restarted the server, replayed the original operation, and checked that its result survived a later push. Reusing an operation ID with a different revision was rejected. A local proxy dropped both a start reply and a status reply after the server handled them. The CLI reconnected and completed the push with the original ID. A separate Windows Companion upload was confirmed by reading the remote branch head. The new CLI also pushed two revisions to a server built from the 0.2.6 tag.

## Upgrade

Deploy the 0.2.7 server and update the Windows MSI or Linux CLI to enable operation tracking on both ends. DynamoDB deployments need permission to put both items of the transaction in the existing mutable-store table.
