## What changed

Lore Platform 0.4.1 lets the server see each client's own address on Linux.

**Client addresses**

- On a Linux server the control plane got the address of Docker's own gateway (`172.x.0.1`) instead
  of the client's for connections Docker forwards through its userland proxy: over IPv6, from the
  server itself, or with the userland proxy turned on. MCP in `internal` mode then refused those
  clients, and the audit log showed the gateway.
- setup now runs Caddy in the host's network on Linux with a rootful Docker Engine
  (`LORE_PROXY_NETWORK=host`). Caddy listens on the server's ports itself and sees every client's
  address over IPv4 and IPv6; the control plane and Keycloak are published on loopback ports
  18081 and 18082 only (`LORE_CONTROL_PLANE_LOCAL_PORT`, `LORE_KEYCLOAK_LOCAL_PORT`).
  `sh setup.sh --proxy-network bridge` keeps the previous layout, which Docker Desktop, rootless
  Docker and `LORE_PROXY_BIND` other than `0.0.0.0` keep by default.
- Docker Desktop on Windows replaces every client's address with its own, so on a Windows server MCP
  is `off` or `on`: `setup.ps1 -Mcp internal` stops and says so. With `on`, every request still needs
  a personal token, and the MCP switch in **Users and groups** decides who may create one.

**Upgrading**

Deploy the 0.4.1 server bundle and run setup. On Linux it switches Caddy to the host's network; the
ports the server listens on stay the same. The loopback ports 18081 and 18082 must be free, or set
`LORE_CONTROL_PLANE_LOCAL_PORT` and `LORE_KEYCLOAK_LOCAL_PORT`. A Windows server with
`LORE_MCP=internal` in `.env` needs `setup.ps1 -Mcp on` (or `off`).
