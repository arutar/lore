## What changed

Lore Platform 0.2.8 makes long pushes visible and self-healing, and fixes the problems an
independent review of 0.2.4–0.2.7 found. **Update the server, the Windows MSI and the Linux CLI
together:** the push protocol moved. A 0.2.7 client and a 0.2.8 server (or the other way round)
still push, but through the old single request that fails after 50 seconds.

**Pushing large commits**

- While the server verifies a pushed revision, the Commit window and `lore push` show what it is
  doing: the step and how many checks it has done.
- A verification has no time limit as long as it makes progress. If it makes none for 5 minutes
  (`push_operation_stall_seconds`), the server restarts it; after three restarts the push fails
  with a message that the commit is saved locally. Before, a stuck verification kept the client
  waiting forever.
- When storage asks to slow down or is briefly unavailable, the server retries the push after a
  pause instead of failing it.
- The server verifies every push at once, however many arrive; 0.2.7 refused pushes past 32.
- Finished push records are removed after 7 days (`push_operation_retention_days`).
- The push protocol now lives in its own namespace, `lore.platform.v1`, so a future upstream Lore
  version can't collide with it. The design is in
  `platform/docs/decisions/0001-push-operations.md`.

**Windows client**

- The Commit window lists changes at once and marks files other people have locked when the
  server answers. Only locks on your branch count: a lock on another branch no longer stops a
  commit.
- Commit works when the list of changes couldn't be loaded, as the window says.
- If a commit is refused before it is recorded, the files you had staged are staged again as they
  were.
- A slow or unreachable server no longer holds Commit at "Preparing files": the lock check gives up
  after 20 seconds and leaves it to the server.

**WebUI and server**

- When your session ends while a page is open, the WebUI asks you to sign in again and brings you
  back to the same page. Before, every page showed "Sign in first" and Retry did nothing.
- Deleting a repository is finished by Lore before the WebUI forgets it. If Lore fails half way,
  the repository stays listed and can be deleted again; closing the browser no longer interrupts
  the deletion.
- `lore clone --identity` keeps the identity you named when it finds a public repository
  anonymously. Before, it could set the clone up with another stored account.

**Releases**

- A release is published, and its container images too, only after the Rust unit, integration and
  smoke tests, lint and the platform checks pass. CI jobs have time limits.

**Upgrading**

Deploy the 0.2.8 server bundle and images, then install the 0.2.8 Windows MSI over the previous
one or replace the Linux CLI. Push records kept by 0.2.7 are not read by 0.2.8.
