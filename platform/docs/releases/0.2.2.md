### What's new

**Windows client**
- **Working copies on network shares.** Clone, commit and status work in a folder such as `\\server\share\project`. Before, a clone onto a share silently landed in `C:\server\share\project` instead.
- **Choose what goes into a commit.** The Commit window lists the changes it would record, each marked new (A), changed (M) or deleted (D), with a box to leave it out. The list is grouped by folder: a folder's box takes in or leaves out everything inside it, and a folder folds to a single row. Everything is ticked by default; files someone else has locked are marked with their name and left out.
- The working copy's `.lore` folder is hidden right after a clone, also when the repository is empty.
- The Commit window no longer grows under the taskbar when its list arrives.

**Server and web interface**
- An Active Directory account an administrator adds shows its login at once and can be found by it. Before, it showed only the email until the person's first sign-in.
- In a public repository, "All signed-in users" is shown as included in public access, since public read already covers everyone.
- The audit log says "on" or "off" for registration changes.
- The repository page header fits a phone screen.
- **Live preview:** the web interface with a fictional studio's data, read-only, at https://arutar.github.io/lore/.

**Upgrading:** the server as usual (below). Windows: install the new MSI over the previous one; working copies stay as they are.
